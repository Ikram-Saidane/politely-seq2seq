# Politely — rewriting impolite sentences politely with an encoder–decoder built from scratch

NLP course project · *Text generation with encoder–decoder architectures*

**Task.** Given a blunt, impatient or dismissive English sentence, generate a polite sentence that
says the same thing.

| Impolite input | Polite output (generated by the final model) |
|---|---|
| Turn the music down. | Could I ask you to turn the music down? Thank you! |
| Again! The package number 7690 was sent to the wrong address last week. | Hi, I'm writing because my package number 7690 was sent to the wrong address last week. I would appreciate your help. |
| You're wrong. Water boils at 100 degrees. | Actually, I think water boils at 100 degrees. Could you double-check? |

The model is a sequence-to-sequence network written by hand in PyTorch (embeddings → LSTM
encoder → Bahdanau attention → LSTM decoder, plus a pointer-generator copy mechanism). No
pretrained model is used anywhere.

---

## 1. Installation

Requirements: Python 3.10 or newer (tested with 3.11 on Windows and 3.12 on Linux). A GPU is not
needed: every model in this project was trained on a 2-core CPU.

**Windows, one click:** double-click `run_app.bat`. The first time, it creates a virtual
environment in `.venv`, installs the CPU version of PyTorch and the other dependencies (a few
minutes), then starts the interface and opens it in your browser.

**Manually (any system):**

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate      Linux / macOS: source .venv/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cpu   # or a CUDA build
pip install -r requirements.txt
pip install -e .                      # makes the `politely` package importable
```

## 2. Launch the interface

```bash
python run_app.py                     # opens http://127.0.0.1:8000
python run_app.py --port 8080 --no-browser
```

The trained models are already in `checkpoints/`, so the interface works immediately.

| Tab | What it shows |
|---|---|
| **Rewrite** | Type a sentence (or click an example) → polite version, politeness before/after, content words kept or lost, warnings (unknown words, repetition…), attention heat map, confidence of each generated word. Choice of model and of decoding (greedy, beam search, sampling). |
| **Compare** | The same sentence rewritten by the two baselines and every trained model, side by side. |
| **Performance** | Success rate and all metrics of every system on the three test sets; learning curves. |
| **Dataset** | Size, balance, splits, quality checks and examples of the dataset. |
| **How it works** | The pipeline in seven steps and the limits of the system. |

Invalid input is handled with a clear message: empty text, only numbers or symbols, more than
300 characters or 40 tokens, unknown model. Words never seen in training are listed in a warning.
The interface is responsive (phone, tablet, desktop) and has a light and a dark theme.

The API is documented at `http://127.0.0.1:8000/api/docs`.

## 3. Reproduce everything

Every step is a module of the `politely` package (run from the project root):

```bash
python -m politely.generate_dataset   # 1. build the dataset            -> data/*.csv
python -m politely.analysis           # 2. statistics and figures        -> reports/dataset_stats.json, reports/figures/
python -m politely.build_vocab        # 3. vocabulary (train only)       -> data/vocab.json
python -m politely.politeness         # 4. politeness classifier (metric) -> checkpoints/politeness_clf.json
python -m politely.train --config configs/B_attention.json --overfit 40   # sanity check: memorise 40 pairs
python -m politely.train --config configs/C_copy.json                     # 5. train one model
python -m politely.evaluate --baselines                                   # 6. evaluate the baselines
python -m politely.evaluate --models C_copy                               #    ... and a model (greedy)
python -m politely.evaluate --models C_copy --decoding beam5 --splits valid   # other decoding
python -m politely.figures --best C_copy                                  # 7. figures of the report
pytest                                                                    # tests (pipeline + API)
```

`train_all.bat` (Windows) and `run_all.sh` (Linux) run steps 5–6 for all eight configurations
(about 3 hours on a CPU). The generator is deterministic (seed 42): it rebuilds exactly the same
dataset.

## 5. Results

Final system: **C_copy_nodrop** (LSTM + attention + copy mechanism, 1.67 M parameters) with
**beam search (5 beams)**, both chosen on the validation set. Success = judged polite AND all
content words kept AND no repeated word. Full tables: `reports/results.md`; analysis:
`reports/report.md`.

| System | test | test_unseen (new phrasings) | challenge (hand-written) |
|---|---|---|---|
| Copy baseline | 0.000 | 0.034 | 0.000 |
| Rule-based baseline | 0.125 | 0.253 | 0.097 |
| A · LSTM, no attention | 0.845 | 0.350 | 0.111 |
| B · + attention | 0.912 | 0.582 | 0.222 |
| **C · + copy, beam 5 (final)** | **0.999** | **0.787** | **0.764** |
| Human judgement of the final system: fully acceptable | 0.975 (40 sampled) | 0.375 (40 sampled) | 0.528 (all 72) |

The model is excellent on sentences like its training data and about half of its rewrites of
free-form sentences are fully acceptable. Bigger models, GRU cells, a lower teacher-forcing
ratio and word dropout did not help (report, section 7.4).

## 6. About the dataset

No public dataset of *impolite-but-not-offensive → polite* pairs of a suitable size exists, so
the dataset was **generated** by `generate_dataset.py` from building blocks written by hand in
`resources.py` (situations, objects, people, times and 108 impolite / 54 polite phrasings over
9 categories). It is therefore **synthetic**: realistic and coherent, but less varied than real
messages. Impoliteness is only a matter of tone (orders, impatience, dismissive remarks): the
dataset contains no insult, swear word or hateful content, and every sentence is checked against
a list of banned words. Splits never share content, and `test_unseen` uses phrasings that never
appear in training. The hand-written `challenge.csv` measures how far the model is from real,
free-form sentences. *This choice should be validated with the professor.*
